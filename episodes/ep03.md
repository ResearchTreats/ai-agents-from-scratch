# EP03 — Write Tool Descriptions an AI Agent Can't Misuse

▶ **Watch:** https://www.youtube.com/watch?v=Rsuf9TKscdk

## What you'll learn

- Write a tool description in the Use when, Do not use for pattern, under 1024 characters
- Name tools in stable, unambiguous snake_case
- Build a linter that flags vague tools and undocumented parameters

## Lesson path

1. Write the naming and description checks
2. Finish parameter checks and lint the box
3. Prove the linter with pytest

## Commands in this lesson

Run these in the VS Code terminal, in this order.

```
python -c "from schema_lint import lint_name_and_description; from tools import helpdesk_tools; print(lint_name_and_description(helpdesk_tools().tools['refund']))"
python schema_lint.py
python -m pytest -q
```

## Try it yourself

Write a get_refund_status tool whose name and description pass the linter, and add it to a toolbox.

## Check yourself

**Q1. A description reads: 'Looks up a customer's order history for support.' What does the linter report?**

<details><summary>Answer</summary>

Two problems: it doesn't start with 'Use when', and it never says 'Do not use'.

</details>

**Q2. Does get_weather_for_tokyo pass the name check?**

<details><summary>Answer</summary>

Yes - the pattern only checks the shape. It still bakes an argument into the name, which the rule never sees.

</details>
